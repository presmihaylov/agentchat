# 03 Room users schema, session room entry, room creation requires login

Status: done (a42c2ca, 2026-09-04)

Ships in one deploy: the server side of session room access and the SPA changes that depend on it. Splitting them would leave a creator as an unlinked member of their own workspace (design section 9).

## Scope
- Migration 000025 (design section 6): `participants.user_id` with the partial unique index `(room_id, user_id) WHERE user_id IS NOT NULL` and the user index, `participants.token_hash` DROP NOT NULL (with the placeholder-hash down), `rooms.created_by_user_id` with its index, FK `users_last_active_room_fkey` on `users.last_active_room_id` to `rooms`.
- Models: `Participant.UserID`, `Room.CreatedByUserID`, `User.LastActiveWorkspaceID` (scanned from `users.last_active_room_id`, JSON key `last_active_workspace_id`); `CreateParticipant` gains a trailing `userID *string` and accepts a nil token hash; `handleJoinRoom` passes nil; new `CreateRoomAs(ctx, name, slug, secret, creator)` (room, admin participant linked to the user, #general, `participant.joined` with `user_id`, one tx, room lock first). The creator's participant name is `display_name` when `validParticipantName` accepts it, else `username`, then `-2`, `-3` against existing rows.
- `ReclaimParticipant` refuses rows with `user_id IS NOT NULL` (`ErrConflict`, same as revoked). Agent rows keep `user_id NULL`, so the agent `/join` path is byte-identical.
- `POST /api/v1/rooms` wrapped in `withSession`: 401 `session_required` for a missing token and for `act_` alike. Cap 5 rooms per creator under `pg_advisory_xact_lock(hashtext('room-create:' || user_id))`, 409 `workspace_quota`. Agents cannot create rooms.
- `authed()` session branch: `participantForSession` reads `X-Workspace-Slug`, one query `SessionScope`; outcomes per design section 4 (400 `workspace_required`, 404, 403 `workspace_forbidden` with `reason: not_member` or `revoked`); updates `users.last_active_room_id` on change. The task 01 `no_room` placeholder goes.
- `POST /api/v1/workspaces/{slug}/enter` with `invite_code`: live participant idempotent, revoked 403, non-member needs a code that opens this slug (else 400 `invite_invalid`), creates a participant linked to the user, never adopts by name.
- SPA: `api()` sends the session plus `X-Workspace-Slug` on room pages (the task 02 act_-wins rule ends); `workspace_forbidden` routing in `api()`; the two 401 reload sites route through the same function; `#enter-view` (invite code only) for session users on `not_member`, the removed notice on `revoked`; the legacy per-slug token key is deleted once a session works; the `/create` block (`isCreatePage`) posts `POST /api/v1/rooms` with the session and lands on `/r/<slug>`; the "Your name" field goes.
- Remove the unauthenticated room create everywhere, in this change (design section 8 lists the files): the `services/api/skill.go` "## Creating a new room" text (agents cannot create rooms; ask your human for a workspace invite code; `/join` cannot reclaim a human who logs in), `services/api/api_test.go` `setupRoom` and the three other create sites, the `scripts/cli-e2e.sh` room-setup line, `scripts/e2e.sh` through `cmd/agentchat create-room --session`, new `scripts/lib/login.js` (`registerAndLogin`, `createRoom`, `loginPage`, `enterWithCode`), and the 48 browser scripts that post to `/api/v1/rooms`.
- Migration note in #agents-backstage before the deploy (removed unauthenticated create, `user_id` in `participant.joined`).
